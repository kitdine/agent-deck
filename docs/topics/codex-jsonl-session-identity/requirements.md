# Codex JSONL 子会话身份与用量归属

## 来源、问题与目标

来源缺陷为 Beads `ad-bug-codex-subagent-jsonl-session-identity`，由 `ad-bug-codex-subagent-usage-attribution` 拆分。v0.7.5 Batch 3 / P2 选择 Lane B：先确定 child、parent、继承历史和计量所有权，再实施 L3 定向回填。价格及实际服务模型映射归 `ad-cost-transparency`。

原缺陷记录中的两例均有独立子线程索引行，模型为空；按来源能找到与该线程累计相符的 input/output，按子 ID 却查不到，用量记在父 ID 下。这证明有错归，不证明 All 已重计、少计或相差某个金额。实现对照为 main `a224b0b`：索引在 `session_meta` 优先取 `payload.id`，但后续 meta 仍能切换索引上下文；用量与工具优先取 `payload.session_id`。首条 meta 的线程身份已被用于 OTel 排他，却不等于事件的执行身份。用量解析及其“像用量”判定只识别旧 `token_count`。子文件可以先包含父历史，再出现子执行，中间没有第二个子 meta。

目标是让每笔可证实的逻辑请求只贡献一次，从实际执行线程查到它的模型、用量和活动。父子明细、会话选择与 All 总量要能对账；证据只能支持局部计数或旧账暂不能交接时，读者应能区分已知小计和完整结果。

## 范围、读面与非目标

只修复现有 Codex 活跃、归档发现范围内的**明文 `.jsonl`**，涵盖来源发现/游标、独立会话索引、用量、工具活动、工作信号、分类，以及决定 JSONL/OTel 排他的写入和结算入口。可观察读面是既有 CLI 列表、搜索、详情（含按需活动）、usage 汇总/统计/信号、遥测及来源状态、桌面 serving 与其已有投影。

本主题没有独立交互 surface，`ux/*.md` 不适用。不新增 UI、命令、配置、公共字段或公共枚举；下文的证据状态用来规定行为，不是新字段。只显示父自身执行量，不增加家族汇总或树形界面。沿用现有价格、支付路由、scope、override、exclusion 和搜索白名单。不改上游、不采集 CPA、不开启 exporter、不重做 credits、guardian 或实验模型映射，不改变其他客户端。

用户 2026-11-17 决定：只剩 `.jsonl.zst` 的历史不自动恢复。发现器不为本主题枚举、打开或解压压缩文件，也不从压缩文件名建立线程或接管计量。支持范围之外且从未登记的历史不可逐条报告；已登记但失去明文的历史按下文缺源规则报告。既有合格 OTel 仍受整线程排他与原准入条件约束。

## 线程、关系与事件归属

下文 P、C、S、G 是合成主线程、子线程、兄弟线程、孙线程的代号，不是路径或账号。判断一条记录前，分别回答以下四个问题：

| 问题 | 成立证据 | 证据缺失或相抵时 |
| --- | --- | --- |
| 这是谁的来源？ | 从已校验代际的字节起点，读到在 turn、消息及计量之前的首个完整 `session_meta`，取其有效 `payload.id` 为来源线程；追加可沿用已验证的同一来源前缀。规范 rollout 名是独立的来源线索（reverted 形状取第一个线程 UUID）；缺头 ID 时须由一致的旧单身份记录或明确本地执行记录交叉印证，才能据名确认来源。改名不改变已证身份。普通单身份旧记录继续兼容既有 `payload.session_id`、顶层 `session_id`/`sessionId`。 | 半个头、只有旧游标或缺决定性记录不能伪造新身份；不得跳过坏头或用中段继承 meta 充当来源头。有效头 C 与规范名 P 不同是**来源冲突**，不择一，也不把二者都列为所有者。独立的无冲突来源仍按自己的证据工作。 |
| 谁是直接父？ | 在来源头的 `payload.parent_thread_id` 或 `payload.source.subagent.thread_spawn.parent_thread_id` 中取明确、有效且一致的直接父。`forked_from_id` 仅表示派生；外层 `session_id` 和 `root_turn_id` 是会话与根 turn 的线索。判等沿用各 ID 类型的既有规范化。 | 直接父缺失、两个位置互斥、自指或组成已知环，都不发布相应的确定父边；已发布边后来成环时，环上的边均不再作为确定关系。保留独立成立的执行事实。G 的直接父是 C，不压平为 P；用途、模型、路由和用户设置都不沿边传递。 |
| 谁执行了这个请求/turn？ | 先看原生记录自身有效的 `thread_id`。`token_usage_record` 上的 `(thread_id, turn_id)` 能把请求连到同一来源段内唯一相符的 `turn_context.payload.turn_id`；该 context 的 `payload.model` 才能用于该请求。两端均已明确线程时按 `(线程, turn)` 对应；只有一端明确线程时，另一端须在相关来源段与已知继承历史中排除同名候选。执行线程与来源线程一致才可从该来源发布本地事实。 | 显式 P 记录出现在 C 副本中是外来证据，不从 C 副本给 P 或 C 发表事实。C 请求自身的线程证据不会被较弱的段线索推翻。若 turn 同时能对应 P、C，不能据裸 `turn_id` 选择 context；只发布该请求自身能证明的部分，模型未知也不借父模型。 |
| 无线程字段的记录属于哪一段？ | 普通单身份来源（只有一套一致的会话身份，无派生、外来或多身份信号）沿用既有 turn 边界。子/混合来源中，记录须显式引用已唯一绑定的本地 turn，或处在**该 turn 的有界执行段**：例如从唯一相符的 `turn_context(t)` 到显式 `(C,t)` 的请求之间，原生顺序完整，中间没有其他 meta、turn 开始、外来线程或继承边界。两端与段内证据必须一致。工具完成还须与同一执行线程、同一调用的开始唯一配对。 | 不把段向开头或末尾无限延长。跨边界、存在缺口、父子复用同一 turn/call 而没有唯一连接时，无锚点的消息、模型、工具、信号及旧通知都不新归 P/C；来源覆盖不完整，可补证重试。仅“没有外来 meta”、文件位置相邻、时间/计数相等、昵称或正文均不是本地执行证明。 |

**先判来源，再判事件。** 对头 C/规范名 P 的这一代明文，即便后面有完整的显式 C 请求，该来源也**零新增发布**：不建 P/C 会话行，不更新任何一方的模型、起止时间或分类，不入搜索/详情、工具、信号、用量、费用或 OTel 所有权。冷建且无别的来源时，列表及搜索无命中，按 ID 无可展示会话；All 中该来源的新增 token、调用和已知金额都是零，覆盖不完整。已有独立 P/C 副本或 OTel 时，相比不含冲突源的对照，其可见贡献不增不减。若旧库曾从该源发表，无法确认执行身份的旧正文不能作为 P/C 的可信搜索/详情命中；旧计量按交接表保全或退出公开侧，不把“零新增”误作删除历史。只有来源冲突本身被纠正并重新校验，或另一独立合法来源提供自己的事实，才能公开相应的新事实。

**请求不是 turn 结束符。** 在混合来源中，请求之后的无线程消息只有在另有本地右边界（如 `event_msg` 的 `payload.type=task_complete`、`payload.turn_id=t`，唯一连到同一 `(C,t)`）且中间无切换、缺口或冲突时，才属于该执行段。此例中 `response_item` 的本地 `message` 仍须过搜索白名单；`role=assistant,phase=final_answer` 的纯可见文本可发布，`commentary`、`partial_answer`、推理和工具结果不是最终回答。无 phase 的旧消息在已证本地段内沿用既有白名单。单凭 `phase` 或裸 `turn_id` 不能证明执行身份。结束后的工具完成也可凭**唯一已证本地开始 + 相同 call ID + 无越界**配对；有多个候选、已切换 turn/meta 或无法证明连续性，则保持开始未完成，不合成时长。EOF、半行或下一条不相关记录不是右锚；后续补足证据再发布一次。

直接父 G→C（非 G→P）、段的起止、消息 phase 判别和来源冲突属于**内部可测的不变量**。以合成解析/归属结果验证，不要求 CLI、桌面或持久公共字段输出父 ID、phase 或段号。公共侧独立验收：G 的会话只出现一次，能查到其自身的模型、允许文本和消耗；P/C 没有代收 G 的调用，不能用这些结果反推已验证了哪一条父边。

继承的 meta、turn、消息、工具或用量不从子副本再次发布；父源缺席也不改变这一点。反之，C 的本地请求不必等第二个 C meta。一个不明历史段不阻塞与其可证分离的请求。列表、搜索、`show --activity`、工具起止、turn 序号、信号、模型分组和计量使用同一执行身份。若后续证据表明 turn 或 call 的连接并不唯一，须撤去只依赖该连接的文档、模型、活动和信号；仍有显式执行身份的请求保留已证计数，恢复不足的部分报 partial。多模型会话的索引摘要沿用首个非空**本地**模型，每次调用仍用自己的模型；缺模型、缺价不抹去已证实的 token。

## 计量与去重

### 计数、请求与镜像

新 `token_usage_record` 以同一执行线程内稳定的 `response_id` 识别响应，`turn_id` 连上下文，取请求级 `usage`。两个不同响应即使同 turn、同一时间、同一计数也可各计一次。`turn_token_usage`、`thread_token_usage` 是累计进度，不作为另一笔调用。缺稳定响应 ID 不以行号、路径、时间或 token 向量造 ID；只有能与既有可识别的旧调用一对一连接时才沿用该调用身份，否则按下表的“仅能证明计数”处理。

以下是**一条明文 JSONL**，所有值均为合成。外层 `type` 是 `token_usage_record`，不是 `event_msg` 中的子类型；`session_id` 可指根会话，`root_turn_id` 不代替本地 `turn_id`，模型来自已绑定的 `turn_context`。不递归查找任意名为 `usage` 的对象；例如 `compacted` 携带的旧计量快照不是新响应。

```json
{"timestamp":"2026-01-02T03:04:05Z","type":"token_usage_record","payload":{"thread_id":"00000000-0000-4000-8000-000000000002","turn_id":"turn-child-a","session_id":"00000000-0000-4000-8000-000000000001","root_turn_id":"turn-root-a","response_id":"resp-synthetic-a","usage":{"input_tokens":30,"cached_input_tokens":10,"cache_write_input_tokens":0,"output_tokens":5,"reasoning_output_tokens":2,"total_tokens":35},"turn_token_usage":{"input_tokens":30,"cached_input_tokens":10,"cache_write_input_tokens":0,"output_tokens":5,"reasoning_output_tokens":2,"total_tokens":35},"thread_token_usage":{"input_tokens":30,"cached_input_tokens":10,"cache_write_input_tokens":0,"output_tokens":5,"reasoning_output_tokens":2,"total_tokens":35}}}
```

形状证据：[上游序列化定义](https://github.com/openai/codex/blob/1b84166252b6ecfd36be9e12c29ac01454a30d7e/codex-rs/history/src/rollout_payload.rs#L36-L66)、[展开的行信封](https://github.com/openai/codex/blob/1b84166252b6ecfd36be9e12c29ac01454a30d7e/codex-rs/history/src/lib.rs#L469-L480)、[请求与计数字段](https://github.com/openai/codex/blob/1b84166252b6ecfd36be9e12c29ac01454a30d7e/codex-rs/protocol/src/protocol.rs#L2575-L2608)及[生产者测试](https://github.com/openai/codex/blob/1b84166252b6ecfd36be9e12c29ac01454a30d7e/codex-rs/core/tests/suite/token_usage_rollout.rs#L89-L113)。该测试区分请求、turn 及线程累计，是普通根会话用例，不证明所有子会话都提供这些值。AgentDeck 候选的 `internal/usage/source_identity_test.go:223–236` 使用的是旧 `event_msg/token_count`，不能作为新形状已被消费的证据。

旧 `event_msg` / `payload.type=token_count` 仅在已确认的执行线程内延续 `info.last_token_usage` 与 `info.total_token_usage` 口径：可比较总量取各分项非负差；首次、重置时有有效 last 则用 last，否则只建新基线；缺 total 使旧基线失效，有有效 last 仍可计。相同快照、纯限流、空通知、无增量不增调用或费用。父历史不能建立子基线。纯旧格式中可识别的独立调用保留原有计量；混合格式不能仅因旧解析曾产生一行就断言另有一次调用。

完整主计数要求**显式** `input_tokens` 和 `output_tokens`，且是可表示的非负整数；给出的缓存、reasoning、cache-write 等分项也必须有效，子集不能大于母项。显式零与缺项不同。缺任一主项、坏数或不相容的分项，单凭该记录不新增确定用量、计量调用或金额，保留可独立验证的事实并报告缺口。总量只加 input + output；cached input 已含于 input，reasoning output 已含于 output，不能再加原始 total、缓存明细或累计快照。某明细在该格式中不适用，沿用既有格式契约；本应提供但未知的明细不补零，主项可证则保留主项，影响定价则金额不完整。cache-write 和历史价格仍按既有口径。

下表约束**同一线程内**的公开结果。“调用”指有证据的计量调用，不是源行数；“计价”还须满足原有模型、价格和路由条件。比较以同一执行段、同一量纲及未重置的累计区间为前提。

| 新旧关系 | 足够的判据 | token、调用、金额及覆盖 |
| --- | --- | --- |
| 可证明同一 | 同一稳定响应重放；或旧 last/差分与新响应逐项一致，且有唯一请求关联，或在同一已界定的单次响应区间内，新旧累计的起止进度和增量一一对应，无其他候选。 | 用请求级事实代表同一笔：token 一份、调用一次、符合定价条件的金额一份。迟到的新镜像**替换**已发布旧代表；迟到的旧镜像不再增加。当前/归档、改名、乱序和重启不改变结果。无其他缺口时完整。 |
| 可证明独立 | 不同稳定响应；或旧调用有独立的本地调用边界，其累计区间与已匹配部分可证不相交。仅数值相等、仅行序不同均不够。 | 每个独立调用的分项、一次调用和符合条件的金额各计一次。旧独立调用与新响应即使同 turn 也不能相互吞掉。无其他缺口时完整。 |
| 仅能证明计数，不能拆为请求 | 有效的本地累计区间可以证明一段 token，但没有稳定请求边界，或多出一段无法分配的余量。须区分“**证明包含**某响应”与“**可能重叠**”。 | 确已包含时，整个区间各分项只计一次；可定位到该区间及原时间桶的已证余量只增加 token，不增加调用，不推算该余量的金额或模型。已识别请求仍各计一次、按原规则计价。若连包含/独立都不能证明，只发布可单独确认的请求，待定区间不叠加；不能唯一定位的分项也不分摊。没有稳定 ID 又没有可核对的区间时，单行不产生公开贡献。上述不确定部分均为 partial，已知小计不是完整总价。 |
| 证据冲突 | 同一 `(线程, response_id)` 出现互不相容的有效计数；不同副本/到达先后不能消除冲突。 | 在识别冲突的发布边界同时撤去该请求原已计的 token、一次计量调用及其金额；不取先到、较大或两者之和。冲突本身不证明某个计数；若另有独立可信区间，只按上一行处理。其他请求照常；覆盖 partial，直到新证据排除冲突，才恢复一笔。 |

这张表适用于冷建或**旧行已经完整定位并可重放**的组；若有不能定位或不能重放的旧行，先执行“谁与谁交接”的判定。只知计数也受整线程所有权约束。先扣除已确认请求覆盖的逐分项区间，只处理剩余的非负分量一次。没有可靠的执行线程、可信区间或必要的计量所有权时，不把孤立计数升为公开消耗。

### 只计 token 的余量如何进入读面

一段已证实的余量不是一次 invocation。以 `C` 的区间增量 20 包含唯一已知响应 R=10、另 10 不能拆为请求为例；R 的合成模型 M、运行时 provider Q、目录单价 1、倍率 2，另 10 没有独立的模型或路由证据：

| 已有读面或过滤维度 | 公开值 |
| --- | --- |
| 请求、会话、客户端、All | 调用列表只列 R=10，分页 total、events、priced/unpriced 调用数、归属原因计数均只按这一笔。C 的会话用量摘要、Codex 与 All 各含 20 token；C 在每个适用的去重会话数中只算一次，不合成“补差调用”、工具或工作信号。 |
| 时间与区间 | 按原始事件时间、既有时区和半开窗口。上下界能把整个余量限制在同一小时/日时，该桶为 20。若只能确认全在同一天却跨两小时，则日/包含整段的查询为 20；两个小时各只含自身可定位的请求，不分摊余量。部分相交的窗口只报已证落入部分并显示覆盖不完整；完全不相交的窗口不受此缺口影响。不能归到更细桶，不得改用扫描日或末行时间。 |
| 模型、运行时 provider | 分别判断，不以 R 的 M/Q、父模型或会话默认值代替证据。只有整段都被同一个已证本地模型上下文覆盖，才能把余量计入其模型行；只有整段均有同一有效路由、无切换/重叠，才能计入其 provider 行。即便某维度确定，也不提升调用数或给余量定价。在本例 M、Q 各仅 10；`--model M`、`--provider Q`、两者联用都仅 10，不能据缺证断言这些就是完整合计。未分配的 10 只在不要求该维度且其他条件均已满足的汇总出现；不新造维度行，不塞进仅用于已判定未归属事件的 `--provider unknown`。 |
| 份额及覆盖 | 未过滤的模型/供应商行之和可小于 All，M/Q 对未过滤已证总量的 token 份额均为 10/20，而非重新归一为 100%。可计价调用仍为 1/1；这一百分比不是金额或来源完整率。不能证明分母完整的费用份额/均价，不给完整值。可确证无关的 client、期间或线程保持自己的覆盖。 |

**金额与来源覆盖分别验收。** 对包含上述余量或不能排除它的切片，`catalog_base_cost=null`、`provider_cost=null`；`known_catalog_base_cost` 和 `known_provider_cost` 只累加已确认调用按现行规则可计入的小计，此例为 10 和 20。没有可计金额的小计用该读面原有的零/不可用约定，绝不作为完整零价。已有 `pricing_complete` 的桌面 usage 及 period totals 必为 `false`；紧凑行用已知金额和 `cost_incomplete=true`。没有该字段的 CLI 用已有 nullable 金额、known 小计以及适用的覆盖通道，不添同名字段。按 M/Q 过滤而无法排除余量也如此；能**证明**该切片不含待核部分时，不因其他切片的歧义把它的金额置空。单条 R 自己仍可显示其完整 10/20。

若旧 20 与 R=10 **仅可能重叠**，只发布 R 的 10 token、一次调用；同一个受影响的汇总也为 `null/null`、已知 10/20、`pricing_complete=false`。冲突致无确定请求、无其他证据时为 0 个已确认调用、0 已知贡献、完整金额不可用。反之，能证明 20 与 10 独立、均按上述价格路由计价时，30 token、2 次、完整及已知金额均为 30/60，`pricing_complete=true`。单纯来源暂未更新时，不把旧版已完整定价的历史请求说成无价；用来源覆盖指明这是旧值。实际有缺价、路由不明或不具备真实支出资格，继续遵守原有目录价/真实支出的分别判定。

### JSONL 与 OTel 的整线程所有权

判定单位是规范的 `(codex, 执行线程)`，不是文件、家族或单请求。**首次接管**要求来源身份无冲突、有至少一笔可独立发布的本地非零计量调用（有凭据的旧调用也可），并且下文的旧账交接允许发布；不要求已知价格或整个文件每一行都可解释。仅头、文件名、工具、信号、累计基线、仅能证明计数的余额或冲突请求都不够。下列四态对即时写入（包括首批前缀）、历史身份补填、启动/周期结算、重建恢复和重启后的再结算一律适用。

| JSONL 证据状态 | 计量所有者与读者所见 |
| --- | --- |
| 未评估 | 读取失败、半行不能定身份、无有效检查点的未验证前缀等不是“没有 JSONL”。对可能受影响的线程，保持上次已证且未失效的单一贡献与相应标记；没有已结算贡献的保持待定。整轮仍报未完成，不妨碍无关线程满足自身条件后的结算。 |
| 身份冲突 | 例如头 C/规范名 P。该来源不能使 C 或 P 接管、撤销、恢复或晋升；两者已有的独立贡献和标记不因冲突而变，未决项保持待定，覆盖 partial。P/S 自身经验证的来源仍然有效。 |
| 已确认身份，尚无可交接的计量 | C 只有头、工具、基线、冲突计数，或首笔请求仍可能与旧账重叠时，可用的本地非计量元数据仍按其读面规则处理。数值不换主：原已合格结算的 OTel 贡献及其会话标记保留，没有则不伪造；新观察保持待定，不把“暂无可发布请求”当作“已确认无 JSONL”。只有区间、连一笔可交接调用都没有时，区间证据待核，暂不进入公开消耗；已有合法 JSONL 调用的线程则可按上表发布已证余量。计量覆盖 partial。 |
| 已接管 | 在首笔可发布 JSONL 计量写入的**同一 core 事务**撤去 C 的全部 OTel 贡献、对应 usage 行及 OTel 会话标记；相应观察不再产生计量，已证 JSONL 调用是唯一来源。之后该线程有局部缺口，只报 partial，不用 OTel 逐请求填洞。反向到达、重复结算也如此；不撤 P/S 的贡献。OTel 标记对应的自动分类证据失效，按新来源刷新，用户覆盖另行核验。 |

未解析来源不等于对所有线程否决。对 S 单独判定：① 同代头、规范名、已核验来源链、显式执行字段或待交接旧行/范围中能具体连到 S 的证据，才把 S 列为候选；C/P 互斥只涉及 C/P，有亲缘、共享根 turn 或同目录都不使 S 入列。② 只有头/工具/半行且无可与 S 重叠的已发布消耗，不能凭“也许是 S”冻结它。③ 特殊情形是**已有公开数值却连候选线程都无法界定**的旧孤儿：暂不新增任何与其可能重叠的 OTel 量，直到用已核验的代际/来源/执行区间证明不交或将不安全旧侧整体退出公开汇总；不要把这类真实旧账风险扩大到所有未读文件。候选可限定为 P/C 时，不得仍以全库未 ready 为由压住 S。

接收/导入只按原有准入、重放和冲突规则保存观察；单凭到达不新增 usage 或会话标记。对没有已确认所有者的新观察，必须有原结算等待期，且合格的有限盘点在 `received_at` 之后、足以排除该线程的活跃/归档明文及旧账重叠，才从 pending 入账。例：S 有一笔已到期 13，只有头 C/名 P 冲突时，符合上述盘点条件的 S 得 13 和标记；若未核前缀的规范名指 S 或旧行可连到 S，S 的新 13 保持 pending、无标记。解除线索后若无 S 计量则结算为 13；若证实 S 有一笔 JSONL 5 则只计 5、无 OTel 标记。S 原本已结算 13 的对照，在仅待核时保留 13 及标记，不撤旧、不叠加新观察。历史补填与重启必须得到相同结果。

旧事件/游标中的 `session_id=P`、历史 `jsonl_owned`、孤立前缀、已保存的头 ID、规范名，都是**待核对的线索**，任何一个都不能单独在另一入口撤回或永久压住 P。重评须包括只有旧 `jsonl_owned` 而没有 pending 行的线程。若证明旧“P 属 JSONL”仅来自 C、P 并无自身 JSONL 计量且无旧账重叠，则解除错误抑制，按原合格 OTel 观察的键、原计数、原事件时间和结算条件恢复 P 的贡献、会话标记及分类，重启也不复发。P 自有合格 JSONL 时则保持 P 的 JSONL 独占。若连旧结论的真伪都不能证明，保持最后单一公开侧并报告未恢复；不得以旧标记充当成功证据。

若旧库本身已经同时公开疑似重叠的两侧，不能假定有安全的单侧旧版。能证明交接的整组一次纠正；不能证明且找不到一致旧版时，保全两侧旧凭据，仅返回可证不相交的小计及 partial，重叠组不作为确定消耗公开。此时既不宣称历史已修复，也不销毁其中任一侧来凑出单一所有者。

**最后一笔 JSONL 失据按以下顺序，而非沿用旧 `jsonl_owned`：**

1. 在同一次所有权重新发布中移出被推翻的调用、金额和绑定；线程无其他合格调用时，连同依附此所有者的 token-only 余量也退出公开侧，凭据保留。若还有一笔有效本地 R2=5，结果就是 JSONL 5、原 OTel 11 不恢复、无 OTel 标记，JSONL 覆盖不全。
2. 若无其他合格 JSONL 调用，对**以前已结算、仅因这次接管而撤下**的 OTel 整线程事实，核对：原观察键、线程、分项及原事件时间仍对应原合法准入/已到期结算；对同一观察键有可复核的原贡献及本次撤回证据（单独一行 `jsonl_owned` 不足）；观察未被 OTel 自身判为冲突、无效，重放按原键只取一次；相关明文/旧账的重新盘点与代际核验已完成，能排除**仍公开或待交接**的同线程 JSONL 量。已经完全重放并明确判为冲突、已撤出的一组，本身不再是未盘点的障碍；“仍有头/冲突行”不单独阻止恢复。满足全部条件时与撤下 JSONL 原子换侧，按原观察恢复 usage、贡献和会话标记。此为恢复旧结算，不重新等待一个时间窗，也不按 JSONL 请求与 OTel 11 逐笔相抵。
3. 否则不恢复：有无法排除重叠的旧侧时按其交接规则保留该侧，绝不再加 11；没有安全旧侧则该线程当前为 0 个**已确认**贡献、无 OTel 标记、覆盖不全。证据补齐后回到第 2 步。仅有从未结算的新观察不享受恢复特例，按上表正常等待；确认为只有无可交接 JSONL 计量的仍待定。以后重新出现合格 JSONL 请求再按首次接管处理。

合成时间序列：P/C/S 原为 7/11/13，C 接管后为 7/17/13；只有 C 的这个响应后来被不同计数推翻。第 2 步全满足则直接回到 **7/11/13，All=31**，C 的 11 在原桶、一次、标记恢复，分类按该标记重算；第 3 步无安全旧侧则 **7/0 确认/13，已知 All=20**，C 无标记，不把 20 报作完整。撤下 17 和恢复 11 之间不能读到临时的两份金额或虚假的完整零；重启及重复结算终值相同。JSONL 证据缺口仍走覆盖通道。

## 历史回填、兼容性与隐私

### 谁与谁交接

以 core schema 35、Codex usage parser 8 和独立 session 索引为基线。只在正常、有预算的扫描/恢复内处理受影响 Codex 来源及相关副本，不能按旧 `session_id=P` 批量改行。无关来源和 Claude 原检查点不被迫回放；存量读取不触发扫描，usage-only watch 不因此打开或创建 session 库。仅当既有持久状态不足以恢复时才申请迁移；三个版本独立管理，编号由主控按目标 main 和已批准在途迁移分配。

**先判断能否替换旧行，再判断它与新请求是否相同。** 发布单位是不能排除相互重叠的整组事实。可定位指能将**每一条待撤的旧贡献**唯一连回原来源代际、字节范围/不可混淆的原事件证据及同一计量区间，不要求它已经匹配到某个新响应。可重放指当前明文或已验证等价的明文副本足以从可信基线重新导出该组**全部**旧贡献，含原分项、时间及边界；“还能打开文件”、数值相等、路径或旧 `session_id=P` 不够。先剥离已经证明独立的真 P/S；哪怕一条未定位旧行仍可能重叠，就不能把剩余整组归作可重放。

| 旧账条件 | 同一、独立、疑似重叠如何结算 |
| --- | --- |
| 无旧公开侧；或旧行全部可定位且可重放 | 重新按来源计算并一次替换，旧解析值不享有保留优先权。相同稳定响应，或唯一同线程本地调用且完整分项、起止累计一一相符，算同一；不同稳定响应或同代不相交的独立本地调用区间算独立。只证明包含就按区间计 token；只是可能重叠则仅计独立确认的 R。**可重放的旧 20 + 新 R=10 且无累计位置 → 10/1，不是保留 20。** |
| 旧行不能定位、不能重放，或只有部分可重放 | 如果仍有耐久证据能唯一证明同一请求（例如同一线程稳定响应、分项相符）且整组无其他候选，可以一对一替换；能证明不相交（例如分别明确 P、C 的本地执行，不是继承副本）则旧新各一次。两者都不能证明时，保留最后安全的旧侧数值、线程和历史绑定，禁止这组新 R 加入 P/C/All 或触发接管。**不能重放的旧 20 + 可能重叠的 R=10 → 旧 20、新增 0、partial**；不是把 R 再加上，也不是擅减为 10。同 ID 的矛盾计数不是同一请求金额已证，应走冲突规则。 |

旧侧暂留只表示最后提交的小计，不确认其归属或完整费用。已经证明失效的金额不再作为已知支出；两个旧侧已疑似重计且无安全旧版时保全凭据，只公开已证不相交的小计。补证后仅对整组一次切换旧键、来源所有权、绑定、时间桶、活动、信号和聚合；历史时间、价格及仍有效的证据不变。来源改写、取消、预算耗尽或并发先提交后从仍有效断点恢复。不能因为一个旧组未恢复而阻塞已证无关请求，也不得让该组通过 watch 或结算旁路换主。连续两轮无变化后逻辑行、数值、标记和绑定稳定。

### 计费与用户绑定

`exact_run` 证明的是**哪个本地执行请求**落在有效 run 的已验证来源字节范围内，不是哪个文件最终提供代表行。不能仅凭旧键、偏移相同、亲缘或时间接近传播它。

| 情形 | 归属要求 |
| --- | --- |
| 一对一重归、键改变 | 已完成且保持 exact 的 run、当时的同一来源代际及范围、范围内的本地执行记录、它与目标请求的一对一关系均成立，延续原 run、provider、multiplier 和 `exact_run`。 |
| 镜像合并、更换代表行 | 同一请求的一个**本地执行**镜像在有效范围内且无相抵的 run 证据，选中的新记录即使在范围外，也只保留一笔原 exact。反之，只有继承副本落在范围内，不能给实际父/子调用制造 exact。 |
| 明文移动或换归档副本 | 原来源区间仍可经已验证的同代字节连续性确认，或以存留的有效范围凭据唯一连接范围内本地镜像与目标请求，才可延续；新路径、同 basename、相同偏移都不够。 |
| 改写、范围失效或多个 run 证据冲突 | 不把失效或矛盾的 `exact_run` 转给新代表。回到既有顺序：按事件时间的有效路由、按逻辑会话起点的 provider 时间线，再到 unattributed；只有独立有效路由仍可给 `exact/effective_route`。不补 multiplier 1，不借父路由。 |

金额守恒仅用于**同一请求集、分项、事件时间、价格和有效路由完全不变**的纯身份重归。镜像去重、补入此前缺失调用、纠正路由、价格覆盖变化分项对账，不能用 All 不变替代核对；不为通过守恒断言修改价格。

分类保留 automatic、有效分类和各自原因。任务子线程无确定维护用途仍在 Work；OTel TUI/exec 标记按既有规则使用。用户覆盖绑定 canonical `(client, session_id)` 和 stable birth。为避免将父历史“出生时间”写入 C，按以下顺序确定本地 `first_at`：

1. 只考虑通过来源判定的 C 自有明文。对每个副本，有效自有头的 `payload.timestamp` 是创建时刻；缺失或不可解析时，才取该头有效的外层 `timestamp`。没有可用的头时刻，取该副本**最早的明确本地执行时刻**：有显式 C 的请求或能唯一连到 `(C,t)` 的本地 turn 开始/context 的原事件时间。仅有无锚消息、子文件里 P 的早期历史、根 turn、文件名时刻、mtime、扫描时间、亲缘、旧错归 P 的 `first_at`，均不入选；没有可信时间就是缺失，不能以空字符串排序挤掉有效时间。
2. 所有时间解析为 UTC 瞬时，同代副本/移动不重复计算。线程存在经核实的自有头时刻，就取这些头时刻的最早有效值；否则才在已证本地执行中取最早值。索引副本用于绑定的起点与这个规范 birth 一致。OTel-only 时沿用原投影中已结算观察的最早有效事件时刻；明文接管后不将已撤 OTel 标记当作仍有效的索引副本来取最小值。示例：P 历史 08:00，C 头内 09:00、头外 09:01，C 首次 OTel 09:05，则 C 的新 `first_at` 是 09:00。头内坏则为 09:01；两个头时刻都坏、只有 C 的本地请求 09:04，则为 09:04。摘要、过滤和绑定不受父历史污染；追加普通后续记录不移动已证出生。
3. 同一完整 birth 且未发现 ID 再用或来源冲突时，原匹配继续有效。若旧 OTel birth 与新 birth 不同，须有独立的一对一连续证据：例如旧绑定对应的出生记录在同一有效来源代际仍能核对，或两侧**实际留有**相同的稳定本地请求身份、分项及可核对时间，能将旧首次观察连到新线程、排除 ID 再用。OTel 不保证携带请求 ID；仅同线程串、相近时间、模型或等量 token 不足。

同一次一致发布中，core `binding_state` 和 `binding_digest`、分类详情及覆盖列表必须一致。可延续时为 `matched`，digest 等于**当前** `(client,C,核实的 birth)` 的既有绑定摘要（birth 不变不改 digest；有等价证据才由旧 digest 转新 digest）；详情 `applied=true`、effective 为覆盖值。不能延续时保留原 digest、值、用户 revision 与撤销能力，core 明确 `unmatched`；`session classify list` 同报 unmatched，详情 `applied=false`、effective 回到 automatic。不可只在读取详情时临时比对而让列表仍报 matched。有限绑定不因发现一个时间就自动升级，恢复出的 unmatched/limited 不自动激活；原生本地未发生身份变化的有限绑定仍遵守既有规则。无用户写入不改其 revision、收据和时间；并发 set/clear 胜过过时的回填判断。重启后即使先读 core-only 的覆盖列表，也不得看到与可发布详情矛盾的新状态。

索引排除优先于所有回填、旧快照与副本选择：session ID 按原 ID 范围，路径只排该来源，项目按已确认项目，client 按既有客户端范围。未排除的合法副本仍按原规则选择；不得借继承副本重新发表已排除文本。Work/Auxiliary/All 是可见会话和工作分析范围；索引排除或 override 不删除消耗，`usage summary` 和 `usage stats` 消耗块仍为 All。

### 两库与投影何时可见

core 已换主但索引仍旧，或两库已更新但共同依赖的分类、信号或 serving 尚未验证发布，均在交接中。阶段和“同一回填代”是**内部不变量**，不是公共字段；稳定的读取向量只能排除读中又有写入，不能证明两库同代。下表的“旧版”必须是相同查询、原事件窗口和权限下上一次已提交且一致的答案；已经被证明泄漏、重复或失效的部分不能当作安全旧版。仅因新版尚未发布，不把没找到安全旧版解释为“该会话不存在”。

### 缺源与清理的优先级

1. **显式用户操作优先，在原作用域内生效。** 排除立即约束可见文档；`purge-index` 清索引，不因保全旧账而恢复被清文本，也不清 core 消耗。获准的明确删除按其原对象执行。盘点没看到路径不等于用户明确删除 AgentDeck 中的旧事实。
2. **有可读的受支持明文副本**：优先用可验证的副本重归或接续；交接成功后才清理被替换的孤儿行、来源、旧绑定/投影，不清真正独立的父行。副本不可读或代际变了，仍按待交接处理，而非删除后再尝试。
3. **升级前已经登记的受影响 Codex 旧来源**（包括旧身份不足以排除错归的候选）：来源消失、不可读或事实上仅剩压缩副本，且无可验证明文替代时，保全优先于 usage 孤儿清理和 session 缺源清理。保留原已提交事件、可核验的 run/范围凭据、聚合、游标、活动/信号及允许保留的索引元数据/文档；不新建猜测事实，不伪称当前源还可按需打开。**未恢复**对外是已知来源覆盖不完整，不承诺一个额外公共原因码或逐源清单：按上表在默认/存量 usage、桌面 coverage 报出；已登记 usage 路径打不开时，`doctor --full` 的 `usage_sources/usage_source_unreadable` 计实际不可读来源，非请求数、无标识；真实重建失败才使用 `usage_source_rebuild_failed` 或 `usage_source_unstable`。目标会话仍有安全的索引文档时可读；明文不存在时 `show` 沿用 `stale`，请求活动时区分 stale/unavailable。若仅 session 曾登记，则由 session 域覆盖、其 serving 投影及相应索引/详情行为反映，不伪造 core 的文件数。不能从“明文缺失”断定“已压缩”。完整交接或遇到对应的显式删除才结束保全。已证无关或已完成交接的来源继续原缺源清理。
4. **从未索引且只有压缩历史**：没有已知旧来源，也没有本主题的 JSONL 事实、缺口条目或数目。只说明扫描覆盖受支持的明文；不能承诺全历史为零或全已恢复。无其他冲突/旧账的合格 OTel-only 线程继续正常结算。

### 隐私边界

身份、turn、请求、源代际与计量只保留既有允许的元数据或必要的非内容凭据。用量、分类、游标和 serving 不保留 prompt、回复、推理、工具参数/结果、命令、凭证或环境原文。来源登记中既有必要的来源定位字段不等于可复制工具目标路径或把路径带入新增诊断。只有独立会话索引及其 FTS/搜索返回可以保留与该本地执行对应的**既有白名单**用户可见输入、最终可见回复；不能把这些文本塞进 `parser_context`、断点、快照或日志。受影响 Codex 半行也不是绕过白名单的渠道：补齐前不得把敏感尾部原文留在持久游标，补齐后仍能从受支持明文安全恢复。验收只用隔离状态和合成数据。

| A7a 分类与排除 | 用 08:00 父、09:00/09:01 子头、09:04 子执行、09:05 OTel 验证 birth 优先级；改名、复制、时区等价时刻及重启不变，无可信时间不凭空补生。OTel→JSONL 另测同 birth、有连续凭据的不同 birth、无连续凭据的不同 birth：前两组 core matched 且 digest 对应新 birth；第三组 unmatched 保留旧 digest。统一发布前后对拍 `session classify` 的 applied/effective、`session classify list` 的 binding_status、Work/Auxiliary/All 数目、搜索与信号，核对自动分类刷新和用户 revision 不变；并发 clear 不复活。分别检查 ID、单个来源路径及合法副本、项目和 client 排除。排除 P 不自动排 C，切换范围或排除索引都不减 All 消耗。 |
| A7b 白名单与负样本 | 用不同的合成哨兵分别放进 P、C 的本地可见用户输入/最终回复，以及 system/developer、隐藏推理、工具参数/结果、完整目标路径、凭证形状、环境及附件字段；另将 P 白名单消息作为 C 的继承副本。允许哨兵在各自未排除会话的搜索/详情各可命中，P 文本不因子副本多一份，排除后不再命中。禁止哨兵在两库所有相关既有/新增字段、FTS 内容、`parser_context`、半行/累计/信号游标、活动/分类、serving/下游快照及诊断、日志、测试输出均为零命中；允许正文也不得流入用量库、游标、serving 或诊断。半行含禁留哨兵时在补齐**前后**分别检查，测试失败只报告分类/位置类型，不回显内容。 |
