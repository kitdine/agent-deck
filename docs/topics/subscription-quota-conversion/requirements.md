# 从会话用量估算订阅额度窗口

本主题承接 `ad-subscription-quota-conversion`。用户想知道一次会话的 API 等价金额、在某个订阅窗口用了多少百分点、照这次的使用组合整窗大致值多少。价源与逐调用资格由 `ad-cost-transparency` 定义。额度来自已交付的 [订阅额度探测](../subscription-quota/requirements.md)，与套餐身份改进独立对账。

## 用户结果

1. 一次选择会话显示一个 API 等价金额，区分完整、部分已知和不可用。选中窗口详情可另显示对应请求片段的分子。
2. 短窗、周窗和不同池分别显示可比较读数及起止。当前客户端只提供共享额度，本版生产结果提供窗口同期变化和条件估值。验收用受控夹具预设独占来证明公式。
3. 定量估值采用 `本窗内匹配的 API 等价金额 / (已用百分点变化 / 100)`，并说明该数值取决于同账号和观察期变化均来自选定会话的假设。账号、重置、计费模式、未采集的其他使用和取整限制显示在受影响的行。

## 证据边界

| 有什么 | 用户看到什么 |
| --- | --- |
| 受控样本同窗仅有 `$6` 的目标用量，已用从 40% 升到 44% | `4 pp`，整窗 API 等价约 `$150`。若另一周窗同批请求只增加 `2 pp`，该窗约 `$300`。真实输出标明独占假设。 |
| Codex 显式测量，配额端点的账号摘要、池和窗口相同，金额及时间范围可用 | 显示 `窗口变化 4 pp`。如果没有已知冲突，给出带「此会话使用该账号、此次变化均来自该时段」假设的条件估值。 |
| Claude 显式测量，两端同一既有探测来源、相同窗口、无已知登录变更，无法验证账号 | 显示 `账号未验证`。在其余条件满足时给出带「测量两端仍是同一账号，且变化均来自此会话」假设的条件估值。无受控采样时只显示可证观察。 |
| 观测到并发、换号、跨重置、池不明确、已知延迟入账或超额模式混合 | 展示能确认的金额和有效读数。标识该窗为何缺少足够的同范围分子或分母。 |
| 两个读数均四舍五入到最接近的 1 pp | 报 `4 pp` 时真实变化约为 `3–5 pp`，同样独占条件下 `$6` 给出约 `$120–$200`。范围只覆盖舍入。 |
| 无变化、数据不完整、观察上限饱和、价格或币种无法求齐 | 保留金额覆盖及读数，给出无法估值的原因。未知与确证零分开。 |

配额是账号和窗口的共享读数。本地仅看到一个会话，无从排除另一设备或其他用量。同一个小幅变化会因舍入、跨来源或服务端入账延迟而变动。旧配额库仅保留最新及前一个值，此前事务和完整端点通常不可恢复。已有逐调用价格可重算，额度缺口单列。[当前存储](../../../internal/store/migrations.go) · [现行观察语义](../subscription-quota/architecture.md)

## v0.8.0 交付边界

首发适用 [CLI 框架](ux/cli.md)。`session show --tokens` 读取已存测量；独立的 `quota sample` 子命令针对已知会话显式采集前后端点。已有设置决定探测权限，无需逐会话配置账号或模型。当前基线的 Codex 与 Claude 对应规则如上，v0.7.5 身份改进可作为未来集成增强。旧库、未启用探测及无法证明客户端适配字段时返回具体原因。

菜单栏和 Widget 的会话估值设计在本主题 `n/a`，保留原有额度读数。会话、账号和测量只保留在本机，App Group 不携带新增数据。本主题使用既有探测网络和隐私限制，估值口径为 API 等价。用隔离的事件和窗口夹具验收。
