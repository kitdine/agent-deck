# 辅助会话识别与工作视图隔离：需求

## 来源与状态

来源为 `ad-auxiliary-session-classification`，从已交付的会话项目归属缺陷
`ad-bug-session-project-attribution-observer-noise` 中拆出的新能力。
v0.7.0 版本契约选择默认隔离、提供切换、保留完整用量和费用；版本成员关系仍由
`feature/v0-7-0-contract` 的 `docs/topics/v0-7-0-contract/tasks.md` 管理。

2026-10-26 用户明确选择：**只隔离后台维护；任务子代理保留在工作视图**。
本文件是待独立评审的需求设计，不代表已实现、评审通过或获准交付。
文档集合与当前状态见 [tasks.md](tasks.md)。

## 目标与非目标

1. 默认工作视图排除已确认的后台观察、记忆整理及其他独立维护会话；保留用户任务及其子代理。
2. 提供工作、辅助、全部三个可发现的查看范围，能查看分类原因并纠正误分类。
3. 列表、会话数、项目数、时长与工作信号采用明确且一致的范围。
4. 总 token、调用量和费用继续完整；未知价格、来源与不可用数据继续显式表达。
5. 重扫、重复来源、迟到元数据与升级后保持身份稳定、结果可解释且可核对。

不增加新客户端支持、不修改 claude-mem 或其他客户端配置、不改变 provider/额度来源、
不重做模型定价、不按 worktree 合并项目、不定义生产力评分、不增加网络服务。
不把子代理并入父会话或改写 canonical ID；是否为子代理与是否为后台维护是两个维度。
本主题不实现项目级或路径级批量分类规则编辑器，不依据正文猜测用户意图。
不实现 Codex 逐会话记忆提取请求与其来源会话的关联（需读取 Codex memories 状态库）；scan-performance 将其交由
本主题或后续主题处理，本主题明确不承接；已登记为 roadmap Backlog 候选与 deferred 协调项
`ad-codex-memory-source-linkage`，不得因此省略或静默关闭。
OTel 采集的开关、支持表与漏计限制（如 Memories 关闭时的标题生成）仍归 scan-performance，本主题只消费已写入的标记。

## 分类契约

分类作用于 canonical `(client, session_id)`，来源副本只提供证据，不增加会话数量。
有效类别为 `work`、`auxiliary`、`unknown`；每条结果必须能够说明来源类型、规则版本、
原因代码、是否为用户覆盖以及原始自动分类。具体字段和存储方案由 architecture 定义。

| 情形 | 必须行为 |
| --- | --- |
| 有明确用户任务来源，或可验证的用户任务父子关系 | work；子代理保留独立身份，不因后台执行或非交互运行而隔离 |
| 有可验证的维护用途来源标记 | auxiliary；包含独立后台观察器/记忆整理，不包含代用户执行任务的代理 |
| 只有目录名、cwd、模型名、会话标题或进程是否交互 | 不足以确认 auxiliary，保留 unknown |
| 来源缺失、无法支持的客户端版本、同级证据冲突 | unknown，报告原因；不静默挑一个来源隐藏会话 |
| 父会话关联缺失或成环 | 不从关系猜测用途；unknown，保留可见 |
| 同一 canonical 会话混合用户任务与维护用途 | 不整条隐藏；unknown，显示混合原因；不在本主题切分事件身份 |
| 用户为指定 canonical 会话设定 work/auxiliary | 显式覆盖优先，保留自动结果和覆盖来源；撤销后恢复当前自动结果 |

自动规则须绑定受支持的来源格式/版本、可复现的脱敏或合成样例及反例。
可组合证据必须包含维护用途证据，不能把两个弱命名线索组合成确定判断。
任务子代理跟随已证明的用户任务用途；维护来源的子代理只有在关系和维护用途可证明时才归辅助。
不得通过模型名称映射价格来反推会话用途。

AgentDeck 自身写入的 `codex-otel-background` 标记是第二个有来源依据的维护来源：它由经实验验证的支持表条目、
会话级源所有权（settle 后仍无 JSONL 证据）产生，不是名称或模型猜测。带该标记的会话自动归 auxiliary；
规则只覆盖标记记录的支持表条目，新增条目须证明其无 rollout 会话属于后台维护后才进入规则，否则 unknown。
晚到 JSONL 使 scan-performance 撤销标记时，该自动证据同步失效，会话按普通 Codex 来源重新归约，不沿用旧 auxiliary。
该来源不提供父会话关联；把 Memories 记忆提取请求关联到其来源会话不属于本主题（见非目标），不据此推断用途。

架构设计必须为至少一种实际后台维护来源给出可验证的识别规则和支持边界，
不能以“全部 unknown”或仅手工覆盖宣称自动隔离已交付。
若现有来源不能提供充分证据，明确返回设计处理可观测性缺口；不静默降低此验收要求。
新增真实日志访问、采样或复制需另行明确授权，本轮不包含这些操作。

## 查看范围与统计

- **工作（默认）**：work + unknown。未知数量必须可见，文案说明它包含来源未确认的会话，
  不能将其描述为“全部已确认的人类工作”。
- **辅助**：auxiliary。
- **全部**：上述并集。三个范围使用同一 canonical 身份、时间窗口、client/project 条件与数据版本。
- 分类/范围过滤先于分页、top-N、最近会话截断与聚合；切换后不得出现列表过滤但 total 未过滤的混合状态。
- 会话数满足 工作 + 辅助 = 全部。项目数按各范围内不同项目集合计数，
  同一项目可同时包含两类会话，因此按集合并集核对，不能相加宣称等于全部。
- 时长沿用各已有指标的时间归属及算法，不把会话跨度改成人工活跃时长。
  可加的会话时长按同一集合核对；区间并集、均值、比例、排序等必须从所选集合重新计算。
  缺失或非法时间不补零；跨天、DST 和并发会话仍遵循既有时间契约。
- Activity/Workflow/Tooling 属于工作分析的呈现采用同一范围；无法与 canonical 会话可靠关联的
  信号属于 unknown 并明确报告覆盖不足，不因关联失败删除原始用量。
- 未关联会话的 usage 事件保留总量，不伪造会话、项目、分类或时长。

总用量、总费用和客户端报告的订阅额度不随工作范围切换减少。
如展示范围内用量/费用，必须另标“所选范围”，保留“全部消耗”并说明时间/事件口径差异。
本主题保证过滤前后底层事件身份、token 和现有计费结果不变；不保证现有价格正确。
观察器 synthetic model 的重复计量须以事件身份/来源证据核对，不因模型名看似合成而扣减。
无法证明同一事件时保留并报告不确定性；模型价格、credits 和别名规则交由 cost-transparency。

## 用户控制与表面

| 表面 | 需求边界 |
| --- | --- |
| CLI 文本与交互会话浏览 | 默认工作范围；提供显式三范围选择、当前范围和未知说明；search/list 同口径；详情按明确 ID 可打开辅助会话并显示类别 |
| CLI 自动化 JSON | 未指定范围时保留现有完整集合、分页行为与旧字段含义；显式 work 选择 work + unknown，显式 auxiliary 只选择 auxiliary，显式 all 选择全部；新增范围元数据，文本默认与自动化兼容默认的差异必须记录 |
| 菜单栏 | 会话列表及工作分析提供工作/辅助/全部切换，工作范围为首次默认；工作统计与所选范围一致，消耗总览保持全部 |
| Settings | 提供默认查看范围、分类说明与覆盖管理入口；准确控件、文案和布局由 UX 决定 |
| Widget | 工作数量必须标明范围；默认与持久化桌面默认一致；只传必要的聚合数和范围，不传身份/正文；沿用系统刷新边界并显示快照时间 |
| desktop wire / App Group | 保留 wire v1 旧字段原义；新增带范围的投影或明确版本方案；旧读者不得把过滤数量当成全部 |

桌面默认范围持久化于本机 AgentDeck 设置，菜单栏临时切换不改变持久化默认；Widget 消费持久化默认。
CLI 显式范围参数优先，文本与 JSON 均按 work、auxiliary、all 的上述集合定义选择，之后再分页；
未指定范围的 CLI 文本默认工作、JSON 默认全部，不读取桌面的临时选择。
JSON 未指定范围且未指定分页参数时仍返回完整集合；显式分页继续遵循既有分页契约。
分类覆盖按 canonical 会话持久化于 AgentDeck 管理状态，重启、重建可恢复，撤销幂等；
不写源日志、不覆盖自动证据、不扩展现有 exclude 规则。
新分类和设置的 backup/restore、purge-index 行为必须由 architecture 明确：普通索引清除不得
意外删除用户覆盖；可移植恢复不得包含源路径或正文，不匹配的覆盖保持未应用而不误套另一会话。

## 正确性、升级与集成约束

默认隔离是展示/聚合选择，不是采集排除、FTS 删除或原始事件删除。
现有用户 exclude 仍生效；“全部”表示现有可见性/权限边界内的全部，不能重新暴露已排除文本。
分类附属元数据不得保存系统/开发者指令、隐藏推理、工具参数/结果、凭据或正文片段。
分类原因只用受控代码和必要的非敏感来源信息；界面不得泄漏完整本地路径。

旧索引无分类时按 unknown 处理并保留可见；重新分类必须支持有界增量处理、失败重试及一致发布。
不得为了切换范围重读全部日志、同步全量扫描或等待外部服务。
分类变更对相关缓存/投影失效，列表和统计同代发布，失败保留旧有效结果并标记 stale/partial。
规则变更可以修正分类，但不能重写事件、session ID、project、源文件或用户覆盖。

与 scan-performance 的集成须在其最终选定内容状态上核验范围索引、重扫和查询成本，
复用其数值预算而不自行豁免或另设替代目标。该主题已合入 `main` `6fff208`，本分支已刷新到包含它的 `660c815`；
不得自建与其 serving 发布、分区失效重复的机制。
与价格主题的集成只协调分类与消耗范围，不将其尚未批准的价格方案作为本主题既定事实。

## 验收矩阵

| ID | 验收条件与证据 |
| --- | --- |
| AC1 分类 | 用户任务、任务子代理、维护源、维护子代理、unknown、伪装目录/模型、混合用途、冲突证据分别验证；至少一个有来源依据的维护适配器；`codex-otel-background` 会话为 auxiliary，晚到 JSONL 撤销标记后不再 auxiliary，无标记的 `otel:` 形状或支持表外条目不误判 |

| AC3 统计 | 同项目两类会话、不同窗口/client、跨天/DST/并发/缺失时间；过滤先于分页；会话分区相加、项目并集及非可加指标按独立 oracle 验证 |
| AC4 消耗 | 切换/覆盖/撤销/重扫前后事件身份、token、全部费用不变；未知价不补零；synthetic 来源重复计量有明确证据或显式未确认状态 |
| AC5 控制 | 首次默认、三范围、临时与持久选择、重启、覆盖/撤销、已有 exclude、详情直接打开及未知提示的 CLI/native 验收；同一窗口含 work、auxiliary、unknown 各一条时，JSON 显式 work 返回 work + unknown，auxiliary 仅返回 auxiliary，all 返回三条；分页及 total 基于所选集合 |
| AC6 兼容 | 未指定范围的 JSON 保留原有完整集合与分页行为，文本仍默认工作；旧 JSON 与 wire v1 字段意义不变；新旧 producer/consumer、缺字段、索引无分类、Widget 聚合隐私与刷新一致性 |
| AC7 恢复 | 重建、purge-index、backup/restore、规则升级、崩溃及发布失败；覆盖保留、源数据不变、旧快照可读，不错误标记完成 |
| AC8 集成 | 与最终扫描实现及工作信号/价格范围联合验证；分类和切换不触发全量重扫，适用性能预算与完整/部分/不可用口径保持；OTel 后台会话的 token/费用留在全部消耗，工作视图会话数不再包含它们 |

后续 tasks.md 分解具体测试及原生验收；本轮不运行产品测试，也不生成实现任务。
文档评审独立于实现验收与 CEv1 完成门；发布、安装及 L4 仍需单独授权。

## 设计交接

输入分类为 SUFFICIENT：用户已解决任务子代理边界，以上为可评审的需求决策。
“全部子代理都隔离”会排除真实用户任务贡献，故按用户选择不采用。
后续 UX 决定具体控件和标本；architecture 必须给出维护来源格式的实证、覆盖优先级实现、
存储/迁移、备份恢复与新旧协议字段方案。若无法满足上述边界，返回需求评审，不自行降级。
