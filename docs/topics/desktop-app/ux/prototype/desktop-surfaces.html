Widgets · four kinds, three sizes

A field is not a reason for a widget; a question is. The projection carries four kinds of fact and a user has four questions, so the set is closed — a fifth widget needs a fifth question, not a fifth field. What changed after review, and why. The first board drew a title bar with a close button, put Settings and Quit in the reading surface, and led with provider switching. A MenuBarExtra popover is dismissed by clicking away — the chrome does not exist, and inventing it was a platform error, not a style choice. Switching is a rare deliberate act; it now lives in the footer menu beside Settings and Quit, where a rare act belongs.
Why four kinds, and why size means depth. The first two boards listed widgets one per interesting field, which produced seven unrelated cards and no answer to why seven. A field is not a reason for a widget; a question is. The projection carries four kinds of fact and a user has four questions about their spend — how much, where it went, whether it is real, when they work — so the set is closed: a fifth widget needs a fifth question. Size then selects depth rather than subject, and each larger family is a superset of the one beneath, which is also how the layout degrades under the largest Dynamic Type sizes. The earlier board violated this by making rhythm a medium and trust a small, so neither question was available at the other size.
The popover uses the same four. Its body is magnitude, composition, trust, rhythm, in that order, with client tabs above and a footer below. Learning one surface teaches the other. Health and warnings are not a fifth section — they qualify the other four, so they render as the banner strip rather than as something else to read.
The data was always there. usage stats returns range, timezone, totals, buckets groupable by hour / day / week / month, models, clients, providers with exact / estimated / unknown attribution, cache_sessions, activity, peak, coverage and unpriced_models — and totals, buckets, models and clients each keep input, output, cached-read and cache-write separately. The terminal report already draws a 7×24 activity heatmap. The first board rendered a fraction of that and the widget document refused systemLarge citing a projection that carried only aggregates. That projection is a contract written days earlier, and treating it as a fact about the world is how a surface ends up poor for no defended reason. It is extended now, with stated bounds — 90 buckets, 12 models, 12 unpriced identifiers — because an extension re-reads it on every timeline refresh.
What a specimen cannot settle. Hierarchy, density, copy, proportion at both widths, and both appearances are reviewable here. Real SF type metrics, Dynamic Type reflow, VoiceOver order, and measured contrast are runtime claims and stay in the manual acceptance checklist.
