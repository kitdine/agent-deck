# 订阅账号与套餐辨识 — Requirements

## 来源与权限

本主题只承载既有 `ad-bug-claude-quota-output-plan`、`ad-bug-codex-quota-plan-display` 的已选范围，不新建产品需求。版本归属由 v0.7.5 契约维护；两个原 Bug 是整体交付的 origin，不因某个文档或局部能力通过就关闭。

## 已知事实与证据边界

- 现有 Codex adapter 读取额度，原 `planType` 作为 opaque 值透传；当前样本 prolite 与同账号官方 App 的 ChatGPT Pro 100、weekly 和 reset allowance 相互吻合。只支持有边界的展示兼容映射，不承诺该枚举在所有未来账户/版本中永久等价。
- 已有只读采样记录 account/read 可提供 email、workspaceName、account type 与 planType；尚未证实它提供能与 rateLimits.accountId 比对的共同稳定 ID。AgentDeck 当前未接入该身份查询。
- Claude Code 2.1.325 的 auth status JSON 样本含 loggedIn、authMethod、apiProvider、subscriptionType/planTier、邮箱及组织字段；旧 CLI/其他认证方式可能不支持。两个既有额度通道仍不提供账号 ID。
- 历史 parse_failed 的坏 stdout 未获得；后续成功两行采样符合旧解析器。不能宣称持续格式漂移，不能用不同时间/安装构建的成功输出证明旧 App 已恢复。
- 当前 Restore 会清空源机器的 quota 观察和通知历史；新增身份具有同样的机器本地性质。

## 探测门禁与预算

- 身份读取是 quota 读取的一部分。读取关闭、客户端非 official 或未被选中时，不启动身份子进程、不发送身份 RPC；手动刷新、view render、旧缓存恢复也不得绕过。
- 读取关闭时，身份与额度一样可以本地保留但不在任何批准表面显示；非 official 和客户端选择切换也不能把旧身份当当前身份展示。
- 身份与 usage 共用既有触发与最小间隔规则；手动刷新仅按既有 quota 规则覆盖间隔，不能覆盖身份独立失败退避、读取开关或 official 门禁。
- 身份失败不阻止 usage 使用自己的预算，反之亦然。两侧均尊重调用者取消和既有刷新总预算，不新增用户超时设置。
- Codex 复用同一个 app-server，不为身份另起客户端。一次 Claude 触发最多一次 auth status 和一次 usage；身份前后重复查询不作为归属证明，不靠反复探测消耗额度。
- 只有实际发起查询才更新最近尝试时间；门禁拒绝不伪造成功或尝试记录。架构分配有界子预算，不能使身份查询耗尽既有 usage 超时。

## 归属证明与身份状态

### Codex

只有两个获准公开响应实际提供共同稳定账号/工作区关联值、值相等且处于同一受控探测上下文，才允许声明新增可读身份与该额度关联。邮箱、套餐、工作区名称相等、同一进程或前后两次读取一致都不足以替代共同键。

当前样本未证实共同键，因此必须支持“身份已识别，但与额度关联未确认”。额度本身仍保留原 accountId 隔离与原 attribution_confirmed 含义；新增邮箱关联状态不能与该布尔值混为一谈，也不展示原始 accountId。

### Claude

本主题内 `attribution_confirmed` 始终 false。auth status 和 usage 使用同一 CLI、环境、配置上下文，但两次独立调用没有共同 quota 账号 ID；前后身份一致只能辅助发现变化，不能把额度升级为已确认归属。

UX 必须覆盖：身份已识别且关联已确认（仅有上述证据的 Codex）、身份已识别但关联未确认、当前身份未知、明确未登录/API-key 模式、上次读取。每个时间标签指向自己的观察，不用当前身份给旧额度命名。

### 变化、失败和在途结果

- 成功且可比较的身份快照出现稳定上下文变化（含组织/工作区）时，Claude 旧额度失效并停止显示，旧世代提醒同时失效。文案只能说明“登录上下文变化，旧额度已失效”，不能声称旧额度已被证明属于上一邮箱。
- 用户于 2026-11-18 确认按 AgentDeck 的通知提交边界验收。Claude 失效事务提交后，AgentDeck 不得发起旧世代提醒的提交调用。此前已提交的提醒，其受理回调和横幅显示时间单独记录为平台观察。
- 后续成功 usage 可作为新的未确认额度显示。身份变化前已在途的旧响应不得恢复已失效缓存；架构必须用探测世代/上下文防止这种倒灌。
- 身份读取失败、不支持或缺少可比较标识不等于已知换号。当前身份降级为未知；旧可读身份只能标“上次读取”并保留原时间，不能与额度组合为当前账号。尚有效的旧 Claude 额度可按旧未确认/真实年龄规则独立显示。
- 明确退出登录/API-key 切换属于已知不再是原订阅上下文，不能继续显示旧订阅身份或旧 Claude 窗口。仅字段暂缺不推断换号。
- 身份关联秘密丢失或变更时不能把新旧键判作同一身份；旧 Claude 上下文额度失效，Codex 原 accountId 隔离不因新展示键被重定义。
- 不新增多账号历史库存或切换功能。被替换的身份不以后台历史账号列表保留。

## 套餐来源与语言

1. 受支持公开接口若明确提供可信、无来源冲突的官方展示名，优先采用；不得猜测未声明字段。
2. 当前 Codex 使用既有原始 planType；只有有依据的 prolite 文案映射到 ChatGPT Pro 100 / Pro 100，未知非空值安全显示原值，缺失有明确原因。
3. Claude planTier/subscriptionType 只有一个非空时采用该来源；二者相同则一致采用；二者不同且无可靠语义证据时显示来源冲突/未知，不猜哪一个是实际套餐。当前已知 pro/pro 可展示 Claude Pro / Pro；其他未知值保留原值，不推断商业等级。
4. 品牌名称在中文和英文界面均保持上述英文名称；周边标签/原因文案覆盖既有中英文。CLI 文本保留旧原始值，JSON/wire 可同时给出原值和显示来源。
5. 显示映射不参与价格、权限或配额计算，不从 Pro 100 推算月费，不把截图价格作为所有地区/渠道价格。

## 隐私数据分类与兼容

| 数据 | 允许处理与保留 | 禁止 |
| --- | --- | --- |
| 原始邮箱、公开账号/组织 ID、身份原始关联字段 | 只在必要的进程内校验/关联计算期间使用，随即转为批准形式 | 原值持久化、wire、日志、通知、一般导出、便携备份 |
| 邮箱显示值 | 持久化前脱敏；仅批准表面可见 | 显示/存储完整邮箱，解析异常时原样回退 |
| 组织/工作区显示名称 | 属于用户已批准的展示信息，可去控制字符、限长后本地持久化并在批准表面显示 | 把原始组织 ID 当名称；日志、告警、一般导出或便携备份携带名称 |
| 不透明身份关联值 | 依赖本机不外流的随机秘密构造，比较所需，区分字段未知与明确无组织 | 裸 ID、无盐邮箱哈希、把脱敏邮箱作为唯一键、在 wire/导出/日志中泄漏关联值 |
| 本机随机秘密 | AgentDeck 自有隐私材料，受状态所有权和私有文件权限保护 | 供应商凭据来源、portable backup、导出、日志或跨机器复用 |
| configDirectory、storedClaudeAiLogin、认证路径、未知附带字段、原始 stdout/stderr/usage 正文 | 解析时按白名单丢弃不需要的内容 | 保存整包诊断或通过错误消息回显原值 |

邮箱须先验证格式：本地部分长度至少 4 时保留首尾各一个可见字符，中间 `***`；长度 2–3 时只保留首字符再加 `***`；长度 1 时全部隐藏。域名作为批准的辨识信息保留，例如 alice@example.test → a***e@example.test。无效值仅给未知原因，不原样显示。

显示名称移除控制/双向控制字符并限制到 64 个可见字符；这只作用于展示副本，不覆盖原始套餐诊断字段。组织名是批准的名称，原始组织/账号 ID 仍禁止外流，二者分类不得混淆。

不透明关联值不得被已知邮箱枚举还原；具体密码学构造、密钥轮换和持久字段由架构定义并验证，不能只把可猜身份做无盐哈希。现有 Codex 额度隔离键保持原语义。

新增字段的 absent/null、未知字段、旧持久化/快照及旧 Swift 消费者必须兼容；身份错误不覆盖有效额度，额度错误不抹掉独立身份状态。

### 备份与恢复

身份展示字段、关联值与本机随机秘密不进入便携备份或一般导出；live quota JSON 是上表单独批准的即时投影，不等于 portable export。Restore 无论档案版本都防御性清空身份和源机器 quota 状态，恢复后只能以目标机器新探测形成当前身份，不能沿用源机器邮箱/组织。架构负责列全涉及的表、快照和备份暂存消费者。

## 诊断、解析与历史收口

- 身份/套餐和 usage 分别记录脱敏失败类别、最近实际尝试、最后成功观察；成功解析“未登录/API-key/无身份”不等于识别了订阅账号。旧展示值保留自己的原观察时间。
- usage 解析错误细分为缺少约定行、形状/数值不合法、时区/时间无法解析；不保存正文。身份查询错误不能覆盖这个类别，反之亦然。
- 覆盖有效两行、缺行、形状/时区异常、额外模型行和旧失败状态恢复。继续只采集约定 session 与 all-models 周窗，额外 Fable/模型行忽略，不扩额度产品。
- 成功刷新应替换旧失败状态并准确更新两侧时间。已知上下文失效后，旧成功时间不能被当作新上下文的成功。
- 原坏 stdout 无法重现时，可按原 Bug 的“复现或明确界定”验收侧收口：明确旧失败时间/构建/调用上下文的已知与未知，完成当前受支持环境的采集/失败恢复、解析矩阵和版本/源码身份绑定，记录“历史根因未复现，未作猜测性 parser 修改”。不声称修好了未知根因。
- 上述诊断处置、账号/套餐全部验收和必需 gate 均满足并授权交付后，才可关闭原 Bug；只界定历史不关闭仍未交付的账号能力。

## 验收矩阵

| 场景 | 必须证明 |
| --- | --- |
| 读取关闭、非 official、未选择，含手动刷新/渲染 | 零身份进程/RPC；保留数据不冒充可显示当前身份 |
| 自动/手动触发及单侧连续失败 | 既有总门禁/间隔规则、身份独立退避、usage 预算与调用者取消不被绕过 |
| prolite、pro/pro、未知/缺失/冲突套餐 | 已批准名称、原值兼容、保守冲突降级，无费用/权限推算 |
| Codex 缺共同键或不一致 | 可读身份关联未确认；原 accountId 额度隔离不变 |
| Claude auth 成功/usage 失败，或反过来 | 两侧来源、时间、错误独立；Claude 归属始终未确认 |
| 已知账号/组织变化、退出登录/API-key | 旧 Claude 窗口失效且不被旧在途结果恢复。失效事务提交后，旧世代提醒提交调用为零 |
| 身份未知/字段暂缺/旧 CLI | 不猜换号，不给旧额度贴新身份；历史值有真实年龄 |
| 旧快照/旧数据库/旧消费者 | 缺省兼容，不丢其他字段或改变 Codex 额度隔离 |
| 原解析支持矩阵与旧失败恢复 | 分类准确、额外模型行忽略、最后成功/尝试时间不混淆 |
| 脱敏、组织名称、关联值及未知字段 | 原值在持久化/投影前处理；批准名称与禁止 ID 分开；无凭据/路径/原始诊断外流 |
| portable backup、一般 export、Restore | 不带身份/秘密；恢复目标不显示源机器身份或额度 |
| 菜单栏与 Widget，中英文 | 一致的套餐/状态与独立身份区域；关闭/失效状态不泄漏旧账号 |
| 历史坏 stdout 不可得 | 当前路径/恢复和构建绑定可验证，记录未复现边界，不假称修复未知原因 |

验证等级 L3；采用隔离账号/CLI/状态夹具，不触碰真实登录。构建与单元测试不代替安装构建身份核验；真实环境变更另需授权。
